# mini_frontend — 청소·Spacefit·Roomquest (Next.js · Vercel)


현재 진행 중이신 `mini_project_backend` 리포지토리 세팅을 보아하니 본격적으로 팀 프로젝트를 시작하시는 단계 같네요! 코드를 작성하기 전에 피처의 개념을 잡고 브랜치 전략을 회의하려는 접근은 협업에서 충돌을 막고 효율을 높이는 **아주 훌륭하고 정석적인 방법**입니다.

궁금해하시는 '피처(Feature)의 개념'과 '회의 시 피처를 나누는 기준'에 대해 명확히 정리해 드릴게요.

---

## 1. 피처(Feature)란 무엇인가요?

소프트웨어 개발에서 피처(Feature)는 '사용자에게 가치를 제공하는 독립적인 하나의 기능'을 뜻합니다.
깃허브에서 '피처 브랜치를 판다'는 것은 메인 코드(보통 `main` 또는 `dev` 브랜치)를 건드리지 않고, 특정 기능 하나만 개발하기 위해 안전한 개인 작업 공간을 복제해 오는 것을 의미합니다.

* **백엔드 관점에서의 피처 예시:**
* 사용자 로그인 API 구현
* 게시글 작성/수정/삭제(CRUD) 기능
* 데이터베이스 스키마 설계 및 초기 세팅
* 결제 시스템 연동



---

## 2. 팀 회의 시 피처를 정리하는 기준 (어떻게 쪼갤 것인가?)

회의에서 기능을 나눌 때는 아래의 4가지 기준을 고려해서 논의해 보세요.

### **① 작업의 크기 (PR 리뷰가 가능한 단위인가?)**

피처가 너무 크면 개발 기간이 길어지고 코드 병합(Merge) 시 충돌이 발생할 확률이 매우 높아집니다. 반대로 너무 작으면 브랜치 관리가 피곤해집니다.

* **기준:** 한 명의 개발자가 **1~3일 안에 끝내고 Pull Request(PR)를 올릴 수 있는 분량**이 적당합니다.
* *Bad:* "회원 도메인 전체 구현" (너무 큼)
* *Good:* "회원가입 API 구현", "로그인 JWT 발급 기능 구현" (적절함)

### **② 기능의 독립성 (다른 작업에 방해가 되지 않는가?)**

A라는 피처가 끝나야만 B라는 피처를 시작할 수 있다면 병목 현상이 생깁니다.

* **기준:** 팀원들이 동시에 각자의 브랜치에서 작업해도 코드가 겹치거나 에러가 나지 않도록 **의존성이 적은 단위**로 나누어야 합니다. (예: 한 명은 유저 API, 한 명은 게시판 API)

### **③ 도메인 및 API 엔드포인트 중심**

백엔드 프로젝트이므로 철저하게 '데이터 모델(도메인)'과 'API 엔드포인트' 기준으로 나누는 것이 좋습니다.

* **기준:** 특정 데이터베이스 테이블이나 관련된 API 묶음을 하나의 피처로 봅니다.
* *예시:* `User` 관련 기능, `Product` 관련 기능, `Order` 관련 기능 등.

### **④ 프론트엔드 요구사항과의 일치 (Client 중심)**

백엔드 기능은 결국 프론트엔드(또는 클라이언트) 화면에서 쓰이기 위해 존재합니다.

* **기준:** 프론트엔드 화면의 특정 버튼을 눌렀을 때 필요한 동작 단위로 피처를 정의하면 협업이 훨씬 매끄러워집니다.

---

## 3. 팀 회의를 성공적으로 이끄는 실전 팁

현재 보고 계신 **깃허브 'Issues' 탭을 적극 활용**하시는 것을 강력히 추천합니다!

1. **회의에서 피처 리스트업:** 브레인스토밍을 통해 구현해야 할 기능(피처)들을 쭉 적어봅니다.
2. **이슈(Issue) 등록:** 나눈 피처들을 깃허브 Issue에 하나씩 등록합니다. (예: `Issue #1: 이메일 로그인 API 구현`)
3. **브랜치 네이밍 규칙 정하기:** 팀원 간 브랜치 이름 규칙을 통일하세요. 가장 널리 쓰이는 방식은 `타입/이슈번호-설명` 입니다.
* *예시:* `feat/#1-email-login` (이슈 #1번인 이메일 로그인 기능을 개발하는 브랜치)


4. **역할 분배:** 각 이슈를 팀원들에게 할당(Assignees)하여 누가 어떤 브랜치를 파서 작업할지 명확히 합니다.

---

팀 회의를 준비하시는 데 도움이 되셨기를 바랍니다. 혹시 이번 백엔드 미니 프로젝트가 **어떤 주제나 서비스(예: 쇼핑몰, 커뮤니티 게시판 등)를 다루는지** 알려주실 수 있나요? 주제를 알려주시면 실제 그 프로젝트에 맞는 구체적인 피처 리스트 예시를 몇 가지 뽑아봐 드릴 수 있습니다!
